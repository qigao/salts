# CNet / CHTTP 有界载荷内存设计

## 背景与事实

CNet 的事件环曾把 `event_capacity * max_payload_bytes` 作为单块内存分配，owner
也一次性分配 `connection_capacity * receive_buffer_bytes`。CHTTP 服务器则为每个连接槽
同时分配最大请求体、两个最大缓冲响应体、最大发送缓冲和 WebSocket 升级暂存区。
这些乘积都是配置允许的逻辑上限，却不应成为初始化阶段的物理预留。

## 候选方案

1. 降低 Flowie 的连接数或单消息上限：实现最小，但改变并发或协议能力，且其他调用方仍会遇到同一问题。
2. 保留按槽位固定载荷：寻址简单，但初始化内存仍随两个独立上限相乘。
3. 固定元数据、按需载荷，并用独立字节预算限流：保持槽位容量与单消息上限，实际内存随在途载荷增长。

选择方案 3。CNet 事件继续由有界 ring 管理顺序，载荷由共享池按事件分配；连接接收缓冲只在连接占用时存在。CHTTP
只预分配解析器和路由所需的小型元数据，大型请求体、响应体、发送缓冲与 WebSocket 暂存区按需增长。

## 状态与错误语义

- 槽位容量仍是事件数、连接数和流数的唯一事实源。
- 新增公开字节预算分别约束 CNet 在途事件载荷与 CHTTP 服务器在途大型载荷。
- 分配前以原子计数保留预算；分配失败或操作回滚时必须归还同一笔预算。
- 超出配置预算返回 `SALTS_ENOBUFS`；系统分配器失败返回 `SALTS_ENOMEM`；单消息超过协议上限仍返回 `SALTS_EMSGSIZE`。
- 载荷 view 的借用期限不变，回调返回后释放事件载荷。
- 关闭路径释放全部按需缓冲，统计中的当前字节最终回到零。

## 公开接口与兼容性

- `cnet_client_config.event_buffer_bytes`：零值保持原有逻辑总上限，但改为按需分配；非零值必须至少容纳一个最大事件。
- `chttp_server_config.buffer_capacity_bytes`：零值保持原有逻辑总上限但不预分配；非零值是所有服务器大型载荷的硬预算。
- 统计公开当前值、峰值和预算拒绝次数，便于生产调优。

字段追加保持源码级零初始化兼容；由于公开 C 结构体布局改变，使用旧二进制头文件的调用方必须与新 Salts 重新编译。
Flowie 显式设置预算，避免把兼容默认值误当作生产资源策略。

## 并发与生命周期

CNet 事件发布可由多个生产者进入，字节计数使用原子 CAS；消费者释放事件后归还预算。
CHTTP owner 线程和 deferred response 线程都可能构造响应，因此预算也使用原子 CAS，不在互斥锁内分配。
缓冲所有权始终留在 connection、parser、response builder 或 H2 stream，销毁和 reset 是唯一释放边界。

## 迁移、验证与回滚

迁移只需为生产配置补充两个字节预算。验证覆盖：大单消息上限下初始化不再产生容量乘积、预算耗尽返回
`SALTS_ENOBUFS`、释放后可再次准入、HTTP/1.1、HTTP/2、WebSocket、TLS 以及 Flowie HTTPS 回归。

若出现兼容问题，可先把新预算设为零恢复旧的逻辑并发上限；实现回滚只需恢复固定载荷数组，不涉及持久化数据或协议格式。
