# CHTTP HTTP/2 And S3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add bounded HTTP/2 client transport to the existing CHTTP sync/async APIs and add an S3 client that depends only on CHTTP.

**Architecture:** Private frame, HPACK and protocol files provide the transport-independent H2 engine. A CNet-owned session adapter multiplexes CHTTP requests without exposing CNet polling or CoroNet types; S3 borrows a CHTTP client and generates one immutable signed wire request.

**Tech Stack:** C11, CNet TCP/TLS, OpenSSL, llhttp for HTTP/1.1, TinyTest, CMake Presets.

**Spec:** `docs/CHTTP_H2_S3_DESIGN.md`

## Global Constraints

- HTTP/3 is not built, imported, negotiated, or used as fallback.
- Existing zero-initialized CHTTP options continue to select HTTP/1.1.
- Explicit H2 failure never downgrades to HTTP/1.1.
- Every growable resource has checked arithmetic and a configurable hard limit.
- Borrowed response/header/data views expire when their callback returns.
- No public API exposes CoroNet or the private H2 engine types.
- Installed consumers do not discover or link `llhttp` or `c-ares` directly.
