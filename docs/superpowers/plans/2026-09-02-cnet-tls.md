# CNet TLS Implementation Plan

## Decision

CNet owns TLS because it owns connection lifecycle and transport progress. NativeIO remains a raw
TCP/UDP/pipe completion layer. CHTTP will consume CNet's TLS and ALPN APIs later; H2 and S3 remain
blocked on that integration.

The implementation uses OpenSSL with a fixed-capacity BIO pair. The CNet owner is the only thread
that accesses each connection's `SSL *`. NativeIO reads and writes ciphertext through two bounded
per-TLS-connection buffers; callbacks continue to receive borrowed plaintext views.

## Public contract

- `tls://host:port` selects verified TLS over TCP.
- Client TLS configuration is copied into an internal OpenSSL context before asynchronous admission.
  URI host verification is mandatory. An explicit server-name override changes both SNI and the
  verified identity; IP literals are verified as IP addresses and are not sent as DNS SNI.
- A `cnet_tls_server` owns a reusable server context. It copies certificate, private-key, client-CA,
  client-auth and ALPN configuration during initialization.
- `cnet_listener_accept_tls()` adopts one accepted TCP socket and begins a server handshake. Existing
  `cnet_listener_accept()` keeps its plaintext behavior.
- `cnet_tls_negotiated_alpn()` copies the selected protocol after `CONNECTED`; it returns `ENOENT`
  when TLS succeeded without ALPN, `ENOTSUP` for plaintext connections, and `ENOTCONN` before open.
- TLS 1.2 is the minimum version. Renegotiation and compression are disabled. There is no insecure
  peer-verification switch.

## Data and ownership protocol

- Fact source: one owner-thread `cnet_tls_state` per TLS session.
- Context: client creation transfers one context reference through the copied connect command;
  server accept retains the reusable server context. The session releases its reference at recycle.
- Plaintext send: the command queue owns the copied application bytes until all corresponding TLS
  records reach a terminal NativeIO write. Exactly then CNet releases the command and emits one
  `on_send(size)` callback.
- Plaintext receive: OpenSSL decrypts into the existing session receive buffer. Its borrowed view is
  valid only during `on_receive`, exactly as for TCP.
- Ciphertext: a fixed-capacity BIO pair provides OpenSSL backpressure. Separate fixed per-session
  read and write buffers bridge the BIO pair and NativeIO. No TLS data path grows without a bound.
- Cardinality: single owner; at most one ciphertext read and one ciphertext write may be active for
  a session. The request pool remains the global hard bound, so TLS can fail with `ENOBUFS` when two
  directions cannot be admitted.

## State, backpressure, and shutdown

1. TCP resolve/connect/adopt completes.
2. TLS enters `PROTOCOL_HANDSHAKING`, installs a separate handshake deadline, drives
   `SSL_do_handshake()`, drains produced records, and arms ciphertext reads as required.
3. Successful verification transitions once to `OPEN`, publishes negotiated ALPN with the connected
   event, and cancels the handshake deadline.
4. `SSL_write_ex()` is retried with the same command bytes after BIO `WANT_WRITE`; ciphertext is
   drained in bounded chunks. A second application write remains rejected by existing `EBUSY`
   admission.
5. Receive demand causes `SSL_read_ex()` and, when needed, one NativeIO ciphertext read. Buffered
   plaintext is delivered one value per owner progress pass to preserve bounded callback work.
6. Local close after an open handshake calls `SSL_shutdown()`, flushes `close_notify`, then closes
   TCP. Peer `close_notify` is clean EOF; transport EOF without it is a protocol failure. Handshake
   cancellation closes TCP directly because no secure channel exists yet.

## Error semantics

- Invalid TLS configuration fails synchronously without publishing a handle.
- Trust loading and key/certificate mismatch return `EIO` during context creation.
- Verification, TLS alerts, malformed records, and unexpected EOF fail the connection at stage
  `handshake`, `read`, or `shutdown` as appropriate.
- Handshake timeout is distinct from TCP connect timeout and reports `ETIMEDOUT` at `handshake`.
- No plaintext downgrade or trust-store fallback is attempted after TLS failure.

## Test sequence

1. Add failing URI/header/config tests for `tls://`, server context, mandatory bounds and ALPN input.
2. Add a loopback client/server test using a test CA: verified handshake, ALPN selection, bidirectional
   bytes, send completion and clean close.
3. Add failure tests for untrusted CA and hostname mismatch; require `FAILED` at `handshake`.
4. Add timeout/cancel and close-notify coverage, then run CNet/CHTTP/CRPC regressions.
5. Verify C and C++ installed consumers link the exported OpenSSL dependency.

## Compatibility and rollback

Existing TCP/UDP/pipe APIs and zero-initialized trailing configuration fields remain valid. A zero
TLS buffer bound disables TLS admission but does not affect plaintext clients. The implementation is
isolated in CNet TLS files and owner branches; rollback removes the new scheme/API without changing
NativeIO or existing transport semantics.
